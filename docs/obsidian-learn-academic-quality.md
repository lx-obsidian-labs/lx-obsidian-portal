# Obsidian Learn | Academic quality management and assessment policy (draft v0.1)
Owner: LX Obsidian Labs. Status: proposed, not accredited, no learner records processed yet. Review with an appropriately qualified academic lead, legal/privacy lead and the applicable quality council before operation.

## Accreditation pathway and evidence
Choose target qualification or skills programme, scope and delivery mode before asserting compliance. QCTO is a possible occupational route; CHE/HEQC applies to higher education programme accreditation where relevant. SAQA establishes NQF assessment principles; no NQF level, credits, qualification title, recognition or accreditation is claimed. Confirm DHET registration obligations and any applicable requirements separately. Identify relevant current occupational curriculum, provider requirements, assessment centre/external assessment requirements and workplace evidence, if required. Create a learning-material matrix, outcome mapping, staff credentials, resources, quality management system, learner-support and results records, and external assessment/moderation agreements. Obtain written approval before using accreditation claims.

## Assessment lifecycle
1. Map each task to measurable outcomes and performance criteria; specify cognitive level, knowledge/practical evidence, marks, conditions, duration, accessibility arrangements, submission format, AI-use rules and reasonable accommodations.
2. Develop student question paper, lecturer memorandum, analytic rubric with performance descriptors, test cases, assessor guide and alternate reassessment instrument. Version and lock final copies.
3. Independent pre-moderation: evaluate alignment, validity, clarity, fairness, difficulty, marks, time, sample answers, code correctness and accessibility. Record changes and approval.
4. Publish candidate instructions and rubric; formative feedback before summative submission. Use supervised independent exercises and oral explain-back where feasible.
5. Intake: verify eligibility, submit private files, issue timestamped receipt, record versions, validate uploads, perform academic-integrity checks.
6. Mark: assessor reviews evidence, automated test outputs and similarity report; records criterion marks, reasons and feedback. AI recommendations are advisory only.
7. Post-moderation: separate reviewer samples random scripts plus borderline, fail, high-risk and disputed cases; compare rubric consistency, resolve discrepancies, record approvals and adjustments. Exact sampling subject to applicable accreditation rules; proposed initial pilot 20% random plus risk cases, 100% of capstone failures and appeals.
8. Release approved results; provide feedback and appeal procedure. Allow a proposed 10 working days to lodge appeal; independent reviewer; decision with reasons; reassessment using equivalent alternate task, not punitive resubmission.
9. Retain auditable results, moderation and appeals records for approved retention periods; monitor reliability, accessibility, turnaround and completion trends. No arbitrary marks or sanctions.

## A01 assessment blueprint (proposed)
Duration: 2 weeks within course schedule; independent work with declared assistance, internet allowed for reference. Deliver a functioning Study Tracker, requirements, wireframe, source files, screenshot, test log, README and 3-minute explanation; recreate or explain a simple change independently. 100 marks: requirements 15 (problem 5, user stories 5, acceptance tests 5); functionality 35 (add 8, toggle 7, delete 7, persistence 8, validation 5); design 20 (semantic HTML 5, responsive layout 7, keyboard accessibility 5, readability 3); tests and safety 20 (five repeatable tests 10, edge/error cases 5, safe rendering/privacy 5); documentation 10 (README 4, reflection 3, source/AI attribution 3). Mark against observed evidence; no marks for unsupported claims. Pre-moderate the final instrument before release. Model answers and reference project only for authorised staff.
## Teaching pack specification
13 editable PPTX packs (one per book); target 25–40 slides per pack, adjusted to content. Each pack: title, prior knowledge diagnostic, measurable outcomes, concept diagrams, accessible code samples, worked example, predict-run-explain exercise, independent task, recap, references, speaker notes with timing/teaching cues and link to approved assignment. Include editable diagrams, captions/transcript for video, descriptive text, sufficient contrast, low-bandwidth PDF version. Version-match book and assessment. Separate restricted instructor memo and slides containing answers. Book 01 prepared as textbook; slide and assessment packs require production and review.
## Academic AI design
Each submission queues a job. Quarantine uploads, enforce size/type, scan malware, parse documents without executing macros, sandbox untrusted code with no network/secrets and CPU/memory/time limits, then compare text n-grams and code tokens/AST against approved corpora. Exclude standard templates, quoted passages, references and repeated drafts with reasons; preserve match locations and provenance. Compare to web/institutional databases only when licensed and authorised. Model reviews are retrieval-grounded with cited passages and uncertainty, not a plagiarism probability; treat submissions as untrusted data (prompt injection), do not execute tool commands from them. AI never changes marks, sanctions, entitlements or sends allegations; assessor reviews evidence, gives learner opportunity to respond, escalates to independent reviewer, logs final reasons. Do not infer authorship from writing style alone. No cross-student identification visible to learners; no submissions to external AI without approved lawful basis, operator terms, privacy notice and transfer review. Apply access minimisation, pseudonymisation, encrypted storage, deletion/retention policy, data subject rights and incident handling. POPIA section 71 automated decisions safeguard; legal review required.
## Release criteria
Before launch: approved academic policies, completed 13 book and lecturer packs, independent technical/pedagogical review, moderated assessment bank, payment/identity/entitlement controls, secure private storage, accessibility and privacy review, staff training, pilot cohort with documented feedback and corrections. No claim that a similarity service or assessment pipeline is already operational.
