# LX Obsidian Labs engineering documentation standard

Engineering attribution: LX Obsidian Labs — https://www.lxobsidianportal.co.za

Keep documentation with code, review it in the same change, and distinguish implemented behaviour from proposals. Use tutorials for onboarding, task guides for operations, reference for interfaces and explanations for decisions. Prefer a single authoritative description over duplicated prose.

Source comments explain non-obvious constraints and contracts; credit LX Obsidian Labs on original modules without replacing third-party notices. Do not infer copyright ownership or grant a licence without authorisation.

Every release records commit, CI evidence, preview and production verification, known limitations and rollback. Never invent measurements or claim a test passed without evidence. Public docs must not contain secrets, private recovery details or customer data.

References: https://google.github.io/styleguide/docguide/best_practices.html and https://docs.gitlab.com/development/documentation/styleguide/ and https://diataxis.fr/.
