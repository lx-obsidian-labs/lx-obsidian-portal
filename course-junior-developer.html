FREE PREVIEW / PRACTICE ACTIVITY

Think like a programmer: inputs, rules and outputs.

Try this original sample exercise. You do not need an account, an AI subscription or a code editor. It is separate from the protected textbook.

01 / Understand the problem

A study tracker has four tasks. Two are complete. The program must count the completed tasks and calculate progress as a percentage.

Input4 tasks, 2 complete
→
Process2 ÷ 4 × 100
→
Output50% complete

02 / Try it yourself

If 3 of 5 tasks are complete, what percentage should the program show?

Choose one answer

03 / WORKED JAVASCRIPT EXAMPLE

Turn the rule into code

const total = 5;
const complete = 3;
const progress = total === 0
  ? 0
  : (complete / total) * 100;
console.log(progress); // 60

The conditional handles an empty task list, so the calculation does not divide by zero.

04 / Extend the exercise

Change the input to 7 of 10 tasks, then test a list with zero tasks. Explain why both results are valid.

Assessment strategy / proposed academic policy

Mastery is demonstrated, not assumed.

Assessment weighting

Book assignments40%
Stage practical checkpoints20%
Knowledge checks10%
Final capstone & defense30%

Assignments A01–A13 carry equal weight within their 40% category. Four checkpoint scores carry equal weight within their 20% category.

Progression and integrity

Proposed completion threshold: 70% overall, at least 60% in every assignment and checkpoint, and 70% on the capstone. Students revise and resubmit weak work after feedback. Critical safety, privacy or integrity failures must be corrected before passing.

AI-generated code must be attributed, explained and tested. Include a short independent exercise at each stage; the learner must be able to explain their own work.

Common assignment rubric / 100 marks

Problem understanding & requirements15
Correctness & functionality35
Code quality, accessibility or appropriate design20
Tests, safety & evidence20
Documentation, reflection & attribution10

Individual assignments use subject-specific criteria mapped to these categories; written AI evaluation assignments assess analytical accuracy rather than code functionality.

Capstone / independent portfolio project

Build a responsible AI study assistant.

Project requirements

  • Responsive interface with an accessible workflow.
  • Backend API with validation and persistent non-sensitive data.
  • AI answers grounded in a small curated document set; source references and refusal when evidence is insufficient.
  • Constrained tool calls, human approval before consequential actions, no exposed API keys.
  • Evaluation dataset, security checks, deployment and README.

Academic quality / accreditation readiness

Formal assessment, fair marking and independent review.

Our proposed assessment framework draws on South African national assessment principles, including validity, reliability, fairness, transparency and appropriate evidence. Obsidian Learn is not accredited; formal approval, qualification mapping and institutional requirements must be completed before any accreditation or NQF credit is claimed.

Assessment instruments

Each of the 13 books will have a diagnostic quiz, formative lab, marked summative assignment, assessment blueprint, candidate instructions, evidence requirements, memorandum and criterion-level rubric. Four practical checkpoints and an independent capstone consolidate the outcomes.

Moderation and appeals

Proposed workflow: pre-moderate tasks and memoranda; mark against published criteria; independently sample marks and borderline cases; record adjustments, feedback, appeals and reassessments. Official accreditation-specific requirements will supersede the draft policy.

PowerPoint lecturer packs

All 13 books have draft editable teaching slides, lesson outcomes, concept diagrams, worked code, live-demo prompts, speaker notes, in-class questions, practical tasks and accessible transcripts or PDF alternatives. Instructor answer slides and marking guides will remain restricted.

Obsidian Academic AI / planned submission monitoring

Evidence-based originality review for every submission.

Every submitted assessment will enter a private review pipeline. Text and code similarity checks will identify matching sources; automated tests will assess functionality; AI will help summarise evidence for academic staff. The system will not label a learner guilty or automatically determine grades or sanctions.

STEP 1

Submit

Private, versioned assessment upload

STEP 2

Check

File safety, citations, source/code matches

STEP 3

Analyse

AI drafts evidence report, not a verdict

STEP 4

Review

Human assessor evaluates context

STEP 5

Moderate

Independent review and appeal route

What the system checks

  • Text matches against an authorised comparison corpus and available sources.
  • Code fingerprints and structural similarity after excluding supplied templates.
  • Missing attribution, suspiciously identical mistakes and inconsistent evidence.
  • Automated test results and optional explanation or live demonstration.

Fairness and data protection

  • Similarity is not proof of plagiarism; legitimate quotations and starter code are excluded where appropriate.
  • AI scores or AI-writing detection are never the sole basis of a penalty.
  • Students can view evidence, explain their work and appeal an adverse decision.
  • Private files, restricted roles, retention rules, secure processing and POPIA review before launch.
Planned system — not operational yet.

No student work is being accepted on this preview. Institutional plagiarism database coverage requires an appropriate licensed service or approved corpus; we do not claim internet-wide coverage.
